# i18n（国际化）指南

## 文件存储位置

| 路径 | 说明 |
| ------ | ------ |
| `apps/app-frontend/src/locales/<locale>/index.json` | app 前端 UI 文案（`en-US` 为源文件，跟随上游 Modrinth/Crowdin） |
| `apps/app-frontend/src/locales-packrinth/<locale>/index.json` | **Packrinth 自有 UI 文案**（AI 工作台等，仅 en-US；与上游隔离，Crowdin 不管理） |
| `packages/ui/src/locales/<locale>/index.json` | 共享组件库（@modrinth/ui）文案 |
| `packages/ui/src/layouts/wrapped/settings/language-settings/language-settings-coverage.generated.ts` | 自动生成的语言覆盖度清单（UI 语言选择器展示依据） |
| `crowdin.yml` | Crowdin 源/目标目录映射与密钥环境变量名 |

- 源语言固定：`en-US`
- 当前语言数：33（`ar-SA`, `cs-CZ`, `da-DK`, `de-CH`, `de-DE`, `en-US`, `es-419`, `es-ES`, `fi-FI`, `fil-PH`, `fr-FR`, `he-IL`, `hu-HU`, `id-ID`, `it-IT`, `ja-JP`, `ko-KR`, `ms-MY`, `nl-NL`, `no-NO`, `pl-PL`, `pt-BR`, `pt-PT`, `ro-RO`, `ru-RU`, `sr-CS`, `sv-SE`, `th-TH`, `tr-TR`, `uk-UA`, `vi-VN`, `zh-CN`, `zh-TW`）
- 语言选择器实现：`packages/ui/src/layouts/wrapped/settings/language-settings/`

### 为什么有 locales-packrinth？

Packrinth 新增的 UI（AI 工作台组件、导航入口）使用 `ai.*`、`app.nav.ai-workbench` 键。它们与上游 Modrinth 的 Crowdin 同步文件隔离存放在 `locales-packrinth/` 中，因此：

- 上游 Crowdin 拉取（i18n-pull）与 `prune-local` 不会删掉/覆盖 Packrinth 的文案
- 合并上游 modrinth 更改时不会与 Packrinth 的 locale 文件冲突（两个文件各自演进）

## 在代码中使用

- 用 `@modrinth/ui` 提供的能力：
  - `useVIntl()` / `formatMessage(messages.foo, vars)` — 普通文案
  - `IntlFormatted` — 富文本（含链接/标签插槽）
  - `defineMessages` / `defineMessage` — 定义带 id 与 defaultMessage 的消息
- Packrinth 自有组件（`src/components/ai/**`、`src/pages/AiWorkbench.vue`）的文案统一以 `ai.*` 前缀命名并写入 `locales-packrinth/`
- 字符串规范转化指南：`.github/instructions/i18n-convert.instructions.md`（提交前把硬编码英文改为 i18n 键）

## 提取新文案（开发时）

```bash
# app-frontend（上游内容，写入 src/locales/en-US/index.json）
pnpm --filter @modrinth/app-frontend intl:extract

# app-frontend（Packrinth 自己的 AI 工作台 UI，写入 src/locales-packrinth/en-US/index.json）
pnpm --filter @modrinth/app-frontend intl:extract-packrinth

# @modrinth/ui（在 packages/ui 目录内）
pnpm --filter @modrinth/ui intl:extract
```

- 作用：formatjs 扫描源码中的 `defineMessage(s)`，分别重写两个 en-US 源文件。
  - `intl:extract` 会忽略 `src/components/ai/**` 与 `src/pages/AiWorkbench.vue`
  - `intl:extract-packrinth` 只扫描这两个目录
- 之后运行 `pnpm scripts i18n-icu-contract prune-local` 清理其他语言里的失效键（仅作用于 crowdin.yml 配置的目录）。

## 清理失效 key

```bash
pnpm --filter @modrinth/app-frontend intl:prune-local
# 或全局
pnpm scripts i18n-icu-contract prune-local
```

CI（turbo-ci.yml 末尾）会强制验证：`intl:extract`、`intl:extract-packrinth` 与 `prune-local --check` 均不产生 diff，否则 PR 被拒绝。

## 翻译获取：来自上游（无需 Crowdin 集成）

Packrinth 的 UI 文案沿用 Modrinth 上游结构。上游 Modrinth 仓库每周合并 Crowdin 翻译 PR（`New translations from Crowdin`），我们通过 `git rebase upstream/main` 同步，**翻译随之自动流入**——因此本仓库不需要自己的 Crowdin 项目，也不存在 push/pull workflow。

- `crowdin.yml` 仅作为 `prune-local` 的源/翻译目录映射（纯本地，无需任何凭据）。
- `pnpm scripts i18n-icu-contract` 仅剩 `prune-local` 一个子命令（离线）。
- 依赖 `@crowdin/crowdin-api-client` 已移除。

```bash
# 更新本地翻译（同步上游后自动体现，无需命令）
git fetch upstream
git rebase upstream/main
```

Packrinth 自有文案（`locales-packrinth/`）为手工维护的 en-US 源 + zh-CN 翻译，不上传任何平台。

## 覆盖度生成（设置页语言列表）

```bash
pnpm i18n:coverage
```

生成 `language-settings-coverage.generated.ts`，必须在提交中保持与 src 更新同步（storybook/prepr 会先执行它）。

## 常见问题

- 为什么上游新英文文案没出现在其他语言里？翻译由上游 Modrinth 的 Crowdin 流程完成；它们合并进 `modrinth/code` 后，通过 `git rebase upstream/main` 同步到本地即可。
- 修改了消息 id 而忘了 prune-local，CI 会报 locale 文件 diff 失败。
- `language-settings-coverage.generated.ts` 被 Storybook/prepr 强制重算；若你手工改了 locales，请先跑 `pnpm i18n:coverage` 再提交。
- Packrinth 自有文案（`locales-packrinth/`，如 AI 工作台）不走上游翻译——手工维护 en-US 源 + zh-CN，其他语言回退到英文。
